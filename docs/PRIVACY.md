# 隐私说明

**一句话：麻薯不收集、不上传、不分析你的任何数据。所有记录、今日简报、助手回答和图谱都留在你自己的设备上，没有服务器参与。**

本说明适用于麻薯（Mashu）v1.1.0 及其仓库中的全部前端代码。最后更新：2026-11-03。

## 1. 我们不收集什么

麻薯没有后端，因此**不存在**以下行为：

- 没有账号、邮箱、手机号或任何身份信息；
- 没有遥测、埋点、崩溃上报、使用统计；
- 没有广告、追踪像素或第三方分析脚本；
- 没有 Cookie 用于跟踪（仅使用 localStorage 保存主题、引导标记、助手人设与安装提示）；
- 没有把记录内容、标题、标签、金额、健康数据、Apple 健康导入内容或搜索词发送到任何地方。

## 2. 内置助手、今日简报与网络

- **助手完全在本机运行。** 自然语言解析、统计、摘要与建议都由 `src/lib/agent.ts` / `src/lib/insights.ts` 中的纯 TypeScript 规则完成；同一份记录、同一个输入和同一个时间必然得到同样的结果。
- **今日简报也是本机计算。** `src/lib/brief.ts` 的 `buildDailyBrief` 是确定性纯函数：读取本地记录，比较昨天与之前有记录的 7 天，生成复盘与建议；没有模型、没有网络、没有后台任务。
- **每日汇总与有依据的助手同样在本机。** `src/lib/digest.ts` 按知识库目录汇总昨天，`src/lib/knowledge.ts` 在本地记录上做确定性检索；它们会返回/渲染 source ids，但只用于打开本地记录，不发出网络请求。历史与计划存在 localStorage（`mashu.digest.v1` / `mashu.digest.schedule.v1`）；没有模型 API、没有远程推送。
- **启动 splash 与首次导览只是本地 UI。** splash、4 屏图谱优先导览和今日的 GraphTeaser 都在本机渲染，不请求网络、不做统计；`mashu.onboarded.v1` 只记录是否看过导览，`?nointro=1` 只是本次跳过 UI 的查询参数。图谱 teaser 从本地目录/记录计数，不发任何请求。
- **不调用任何模型 API，不把记录交给云端或大模型。** 助手不是大语言模型，简报也不是 AI 服务；没有模型权重、没有推理请求、没有第三方 SDK。
- **没有推送服务器。** 应用不会在后台运行，也不会注册远程推送。固定时间提醒依赖 iOS 自带的「快捷指令 → 自动化 → 每天」打开麻薯——这是操作系统在你的设备上执行的动作，不需要服务器。
- **对话只存在当前页面内存里。** 刷新或关闭页面即清空；只有你在草稿卡片上点「保存」后，记录才写入本地数据库。
- **助手人设保存在本机。** 名字与节点式头像（Mochi Node / 抽象节点预设，或自定义字符）存在 localStorage 的 `mashu.agent.v1`，不会同步或上传。

应用本身也不依赖任何后端或第三方接口：构建产物是静态 HTML/CSS/JS，运行时的网络访问只用于加载应用自身的同源静态文件（页面、JS/CSS、图标、manifest、iOS 启动图）。没有 CDN、在线字体、远程图标或统计脚本；暖纸/暖炭界面、细边框、Mochi Node 品牌符号与节点式头像全部由本地 CSS/SVG 渲染。

**没有服务器，也没有账号。** 正式发布路径是 GitHub Actions 自动把静态站点发布到 GitHub Pages：GitHub 只是免费的静态托管方，维护者不做任何服务器运维，也没有后端数据库。用户用 Safari 打开 HTTPS 地址、分享 → 添加到主屏幕后，首次加载完成即可离线使用；之后所有记录与计算都只在这台设备的浏览器里进行。首次加载之后，运行时不需要网络（更新时除外）。

例外只有你主动写入的内容：如果你在 Markdown 里放了网络图片或外链，预览/点击时浏览器会按你写的地址去加载；这属于你主动发起的内容请求，应用不会读取或中转。

开发/发布工具（`npm run dev`、`share`、`qr`、`screenshots`、`icons`、`splash`）只在本机或局域网提供/处理静态文件，不涉及记录内容。

## 3. Apple 健康导入的隐私

Apple 健康数据是麻薯里最敏感的一类内容，处理方式如下：

- **只在设备上解析。** 「更多 → 设置 → Apple 健康 → 连接 Apple 健康」选中的 JSON/CSV 文件由 `src/lib/health.ts` 在浏览器内存中读取、解析、单位换算和聚合；文件不会被上传，也不会经过任何服务器。
- **没有 HealthKit 直连。** 网页应用没有健康 App 的权限，麻薯不会、也无法直接读取 HealthKit。当前的零服务器路径是「文件导入」与「快捷指令 URL 导入」；原生 iOS 壳（Xcode + HealthKit）只是路线图选项。
- **快捷指令 URL 的注意事项。** `?health=<数据>` 会出现在浏览器地址栏，可能被 Safari 历史记录、剪贴板或截图保留；如果你介意，**优先使用文件导入**。应用处理完会立即从地址栏移除该参数，但这不能清除系统历史记录。
- **重复导入不会重复建记录。** 同一本地日期 + 同一健康指标会通过 `replaceId` 更新已有记录；聚合在本地完成。
- **导出的健康数据是明文。** 备份 JSON/Markdown 里的心率、体重、睡眠等字段没有额外加密；请像保管体检报告一样保管导出文件。

## 4. 数据存储在哪里

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 全部记录 | IndexedDB：数据库 `mashu`，schema v2，对象仓库 `notes` | 默认存储方式；包含生活记录、笔记、知识库目录（`meta.directory`）、归档/计划字段与 Apple 健康导入后的指标记录 |
| 全部记录（回退） | localStorage：`mashu.notes.v1` | 仅在 IndexedDB 不可用（隐私模式、被禁用、配额不足）时使用 |
| 主题偏好 | localStorage：`mashu.theme.v1` | 浅色 / 深色 / 跟随系统（默认浅色） |
| 引导标记 | localStorage：`mashu.onboarded.v1` | 是否已看过首次新手导览；也沿用作首次演示记录播种标记。只在本机 |
| 助手人设 | localStorage：`mashu.agent.v1` | 助手名字与节点式头像（Mochi Node / 抽象节点预设 / 自定义字符） |
| 安装提示状态 | localStorage：`mashu.installHint.v1` | iPhone 首次打开的「添加到主屏幕」提示是否已关闭 |
| 每日汇总历史 | localStorage：`mashu.digest.v1` | 最近 14 天的汇总（按 dateKey 去重），只在本机 |
| 每日汇总计划 | localStorage：`mashu.digest.schedule.v1` | `{ enabled, time }`，默认开启、08:00；只在本机 |
| 模块可见性 | localStorage：`mashu.modules.v1` | LifeOS 模块隐藏列表（偏好） |
| 应用壳缓存 | Cache Storage：`mashu-v1` | Service Worker 维护，只有静态资源，不含任何记录 |

> 关于 `rixin` / `mochi` / `inkstone`：它们是更早版本使用过的**内部代号/数据库名**。1.1.0 会在首次打开时把旧数据库与旧 localStorage 键中的数据与偏好一次性迁移到 `mashu`，只有成功写入后才删除旧副本；它们不再是产品名，也不会作为新的存储键使用。

「更多 → 设置 → 高级设置」默认折叠，只是把本机已有的技术信息展示出来：导出为 Markdown、快捷指令 URL scheme、存储引擎（IndexedDB / localStorage）与用量、旧版本迁移说明、Apple 健康导入的 JSON/URL 格式与 HealthKit 限制；项目主页与开源许可链接在「关于」里。展开这些信息不会产生新的数据、网络请求或上报；它只是让高级用户能看到格式与限制。

**知识库目录与每日汇总的本地性：** 目录笔记与 `dirId` 归属是普通记录字段；删除目录只解除归属，不会删除成员。每日汇总历史/计划只存在 `mashu.digest.v1` / `mashu.digest.schedule.v1`，按本机时间在打开应用后生成；「有依据的助手」的检索、统计与拒绝都在本机计算，来源 chips 只打开本地记录。它们不会把内容发送到任何服务器，也没有模型调用。

要点：

- 数据保存在**当前浏览器 + 当前 origin** 下。`localhost`、`127.0.0.1`、局域网 IP、部署域名在浏览器眼中是不同的站点，各有独立的记录库；换地址访问会看到空库，这不是数据丢失。
- 同一台设备的不同浏览器（Safari / Chrome）、同一浏览器的普通/隐私窗口之间也互不共享。
- **iOS 上的存储归属**：记录属于该网站 / 主屏幕应用的浏览器存储。删除主屏幕图标通常只是移除入口，未必删除数据；但**清除 Safari / 网站数据、系统清理或卸载相关数据会删除记录**。不同 iOS 版本的提示和行为可能不同，请以系统实际表现为准，并定期导出备份。
- 浏览器可能清理「不常访问站点」的数据。应用启动时会调用 `navigator.storage.persist()` 请求持久化权限以降低概率，但**不能保证**；定期导出备份是唯一可靠的保护。
- 设备上安装的「添加到主屏幕」版本与浏览器页面共享同一 origin 的存储；不要假定它们会自动同步到其他设备。
- 升级到 1.1.0 时，更早版本的数据库（`rixin` / `mochi` / `inkstone`）会在首次打开时迁移到 `mashu`；IndexedDB 仍会在原库上按需升级到 schema v2。知识库目录、归档/计划字段和每日汇总历史都是本地数据；splash/导览偏好也只在本地；旧版 JSON 备份也可以直接导入。仍建议在升级前导出一份 JSON 备份。

## 5. 生活数据比较敏感

麻薯会记录收支、体重、睡眠、心率、饮食等信息，这些数据比普通笔记更私人。请注意：

- 浏览器的 IndexedDB / localStorage **不是端到端加密存储**；能解锁你设备或浏览器配置的人可能读到它们。请为设备设置锁屏，必要时使用系统级磁盘加密。
- 导出的 JSON / Markdown 文件是**明文**，包含全部结构化字段与 Apple 健康导入结果；请像对待银行账单或体检报告一样保管，不要随手发到公开群聊或 issue。在 iPhone 上，导出会经过 iOS 系统分享面板，选择存到「文件」还是 iCloud 云盘由你决定；iCloud 只是你选择的存放位置，**不是应用内置的同步**。
- 应用没有云端副本，因此也不存在「服务商泄露」的问题，但代价是：设备或浏览器数据被清除时，记录就真的没了。请定期导出备份。
- 换手机没有自动同步：在旧手机导出 JSON → 存到「文件」或 iCloud 云盘 → 在新手机导入。iCloud 同步功能目前**不存在**。

## 6. 局域网分享会暴露什么（仅开发者调试）

`npm run share` 是开发者真机调试工具，**不是普通用户的安装路径**。它使用一个只读的静态文件服务器，把构建产物 `dist/` 暴露在 `0.0.0.0:4173`：

- 同一局域网内的设备可以打开麻薯的**应用界面**；
- 服务器不读取、不转发、不存储任何记录；
- 每台设备打开后都使用**自己浏览器里的独立记录库**，手机看不到电脑上的记录，反之亦然；
- `npm run qr` 生成的二维码图片（`docs/screenshots/lan-qr.png`）只包含局域网 URL，不含任何记录内容；
- 分享结束后（Ctrl+C 停止脚本），局域网暴露即消失；
- 普通用户不需要运行它：安装到主屏幕的正式路径见 README；如果你不希望应用出现在局域网中，不要运行 `share`。

## 7. PWA、Service Worker 与离线的边界

- 仓库内提供 `public/manifest.webmanifest`、`apple-mobile-web-app-*` meta、`apple-touch-startup-image` 启动图和用于应用壳缓存的 `public/sw.js`；从 Safari「添加到主屏幕」后以 `display: standalone` 打开。
- 生产构建会在页面 `load` 后注册 Service Worker，但浏览器只允许在 `https://` 或 `localhost` 等安全上下文中注册；通过 HTTP 局域网地址访问时注册会失败，应用以在线模式运行（记录数据仍保存在本地）。
- **构建时注入缓存清单**：正式 `npm run build` 会在 Vite 构建后运行 `scripts/sw-precache.mjs`，把带 hash 的静态资源写入 `dist/sw.js` 的 `PRECACHE`（`splash/` 由 iOS 系统直接读取，被排除）。
- Service Worker 只缓存应用壳：入口 HTML、manifest、图标以及同源静态资源（Cache Storage 名称 `mashu-v1`）。它**不会读取、缓存或上传 IndexedDB / localStorage 中的记录**。
- **更新方式**：联网时重新打开主屏幕图标，导航请求会走 network-first 拉取新版本并更新缓存；离线时使用最近一次缓存的应用壳。没有应用内更新弹窗，也不会在后台静默上传任何数据。
- 无论是否启用离线缓存，记录始终只存在本地浏览器存储中。

## 8. 如何备份、导出与删除

### 导出备份（推荐定期做）

1. 打开麻薯底部导航的「更多」→「设置」页。
2. 在「数据与隐私」选择「导出完整备份（JSON）」：得到包含全部记录的 `.json` 文件（vault v2，顶层 `app` 标识为 `mashu`），可再次导入。**知识库目录是普通笔记，所以会自动包含在备份里**；归档/计划字段也会保留。iPhone 上会打开 iOS 系统分享面板，可选择「存储到『文件』」或 iCloud 云盘；不支持 Web Share 文件时会回退为普通下载。
3. 或从「高级设置」选择「导出为文本（Markdown）」：得到一份便于阅读/迁移到其他工具的 Markdown 合集（注意：该格式目前不能导回麻薯）。
4. 把文件保存到你信任的位置（本地磁盘、加密网盘等），并妥善保管——其中包含收支与健康数据。

### 删除单条记录

在「经历」列表、编辑器或图谱的记录信息面板/目录页中删除；操作会立即写入本地存储。删除目录只会把成员移出目录，不会删除成员记录。

### 删除全部数据

1. 「更多 → 设置 → 数据与隐私」→「清空全部记录」——会移除 IndexedDB 与 localStorage 中的全部记录（主题、引导标记、助手人设、安装提示、每日汇总历史/计划可能保留，可一并清除站点数据）。
2. 或在 iOS 的 Safari 设置 / 系统设置里清除该网站的数据（「Safari → 高级 → 网站数据」，或「设置 → Safari → 清除历史记录与网站数据」）。这会一并删除记录与偏好，且不可恢复。
3. 删除主屏幕图标通常只是移除入口，**不保证**删除数据；反之，清除网站数据会删除记录。以 iOS 实际行为为准，删除前请先导出 JSON 备份。

## 9. 第三方组件

麻薯的运行时依赖只有 `react`、`react-dom`、`markdown-it`，全部在你自己的浏览器中执行，不与它们的维护者通信。iOS 的分享面板、「文件」和 iCloud 云盘属于系统能力：只有你在导出时主动选择，文件才会进入这些位置；应用本身不上传、不读取它们。开发/发布工具（Vite、TypeScript、Vitest、`qrcode`、`qrcode-terminal`、Python + Pillow 及截图脚本使用的本机 Chrome）只在本地运行。没有接入任何第三方服务、SDK、模型 API 或统计平台。

## 10. 政策变更

如果未来版本引入了需要联网的功能（例如可选的云同步、iCloud 同步，或路线图中的本站本地小模型适配器），我们会：

- 默认保持**关闭**，由用户主动开启；
- 在开启前明确说明会传输哪些数据、传到哪里（本地模型适配器仍应在设备本地运行）；
- 同步更新本文件与 README，并在版本说明中标注。

目前 iCloud 同步、云同步都不存在；导出到「文件」/ iCloud 云盘只是手动备份文件。可选的 App Store 壳（Capacitor）或原生 iOS 壳（Xcode + HealthKit）若未来实施，原生壳在读取健康数据时会先向用户申请系统权限，默认不改变「数据留在设备本地」的行为，除非另行说明。

在此之前，本说明第 1、2 节所述行为不会改变。

## 11. 联系方式

如发现隐私/安全问题，请通过 GitHub 仓库维护者的主页联系方式私下沟通，不要公开提交包含敏感信息的 issue；尤其不要附带真实的 Apple 健康导出或生活记录备份。
