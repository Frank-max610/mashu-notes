# 隐私说明

**一句话：麻薯不收集、不上传、不分析你的任何数据。所有记录都留在你自己的浏览器里，内置助手完全离线，没有服务器参与。**

本说明适用于麻薯（Mashu）v0.3.0 及其仓库中的全部前端代码。最后更新：2026-11-03。

## 1. 我们不收集什么

麻薯没有后端，因此**不存在**以下行为：

- 没有账号、邮箱、手机号或任何身份信息；
- 没有遥测、埋点、崩溃上报、使用统计；
- 没有广告、追踪像素或第三方分析脚本；
- 没有 Cookie 用于跟踪（仅使用 localStorage 保存主题、引导标记与助手人设）；
- 没有把记录内容、标题、标签、金额、健康数据或搜索词发送到任何地方。

## 2. 内置助手与网络

这是 0.3.0 最需要说清楚的部分：

- **助手完全在本机运行。** 自然语言解析、统计、摘要与建议都由 `src/lib/agent.ts` / `src/lib/insights.ts` 中的纯 TypeScript 规则完成；同一份记录、同一个输入和同一个时间必然得到同样的结果。
- **不调用任何模型 API，不把记录交给云端或大模型。** 助手不是大语言模型，没有模型权重、没有推理请求、没有第三方 SDK。
- **对话只存在当前页面内存里。** 刷新或关闭页面即清空；只有你在草稿卡片上点「保存」后，记录才写入本地数据库。
- **助手人设保存在本机。** 名字与头像存在 localStorage 的 `mochi.agent.v1`（内部代号见下文），不会同步或上传。

应用本身也不依赖任何后端或第三方接口：构建产物是静态 HTML/CSS/JS，运行时的网络访问只用于加载应用自身的同源静态文件（页面、JS/CSS、图标、manifest）。没有 CDN、在线字体、远程图标或统计脚本。

例外只有你主动写入的内容：如果你在 Markdown 里放了网络图片或外链，预览/点击时浏览器会按你写的地址去加载；这属于你主动发起的内容请求，应用不会读取或中转。

开发/发布工具（`npm run dev`、`share`、`qr`、`screenshots`、`icons`）只在本机或局域网提供/处理静态文件，不涉及记录内容。

## 3. 数据存储在哪里

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 全部记录 | IndexedDB：数据库 `mochi`，schema v2，对象仓库 `notes` | 默认存储方式，容量较大；v2 新增记录类型、结构化字段、手动连线与图谱位置 |
| 全部记录（回退） | localStorage：`mochi.notes.v1` | 仅在 IndexedDB 不可用（隐私模式、被禁用、配额不足）时使用 |
| 主题偏好 | localStorage：`mochi.theme.v1` | 浅色 / 深色 / 跟随系统 |
| 引导标记 | localStorage：`mochi.onboarded.v1` | 是否已写入演示记录 |
| 助手人设 | localStorage：`mochi.agent.v1` | 助手名字与头像（预设或自定义 emoji） |
| 应用壳缓存 | Cache Storage：`mochi-v2` | Service Worker 维护，只有静态资源，不含任何记录 |

> 关于 `mochi`：这是项目早期的**内部代码代号**，只出现在源码标识与存储键里，用于兼容 0.2.x 及更早版本的数据；产品名与界面一律叫「麻薯」。

要点：

- 数据保存在**当前浏览器 + 当前 origin** 下。`localhost`、`127.0.0.1`、局域网 IP、部署域名在浏览器眼中是不同的站点，各有独立的记录库；换地址访问会看到空库，这不是数据丢失。
- 同一台设备的不同浏览器（Safari / Chrome）、同一浏览器的普通/隐私窗口之间也互不共享。
- 浏览器可能清理「不常访问站点」的数据。应用启动时会调用 `navigator.storage.persist()` 请求持久化权限以降低概率，但**不能保证**；定期导出备份是唯一可靠的保护。
- 设备上安装的「添加到主屏幕」版本与浏览器页面共享同一 origin 的存储。
- 升级到 0.3.0 时，IndexedDB 会在原库上就地升级到 schema v2（为旧记录补默认类型与空的结构化字段），0.1.x 的旧库会在首次打开时迁移进来；旧版 JSON 备份也可以直接导入。仍建议在升级前导出一份 JSON 备份。

## 4. 生活数据比较敏感

麻薯会记录收支、体重、睡眠、饮食等信息，这些数据比普通笔记更私人。请注意：

- 浏览器的 IndexedDB / localStorage **不是端到端加密存储**；能解锁你设备或浏览器配置的人可能读到它们。请为设备设置锁屏，必要时使用系统级磁盘加密。
- 导出的 JSON / Markdown 文件是**明文**，包含全部结构化字段；请像对待银行账单或体检报告一样保管，不要随手发到公开群聊或 issue。
- 应用没有云端副本，因此也不存在「服务商泄露」的问题，但代价是：设备或浏览器数据被清除时，记录就真的没了。请定期导出备份。

## 5. 局域网分享会暴露什么

`npm run share` 使用一个只读的静态文件服务器，把构建产物 `dist/` 暴露在 `0.0.0.0:4173`：

- 同一局域网内的设备可以打开麻薯的**应用界面**；
- 服务器不读取、不转发、不存储任何记录；
- 每台设备打开后都使用**自己浏览器里的独立记录库**，手机看不到电脑上的记录，反之亦然；
- `npm run qr` 生成的二维码图片（`docs/screenshots/lan-qr.png`）只包含局域网 URL，不含任何记录内容；
- 分享结束后（Ctrl+C 停止脚本），局域网暴露即消失；
- 如果不希望应用出现在局域网中，不要运行 `share`，改用部署好的 HTTPS 地址或本机 `localhost`。

## 6. PWA、Service Worker 与离线的边界

- 仓库内提供 `public/manifest.webmanifest`、iOS / Android 的「添加到主屏幕」meta，以及用于应用壳缓存的 `public/sw.js`。
- 生产构建会在页面 `load` 后注册 Service Worker，但浏览器只允许在 `https://` 或 `localhost` 等安全上下文中注册；通过 HTTP 局域网地址访问时注册会失败，应用以在线模式运行（记录数据仍保存在本地）。
- Service Worker 只缓存应用壳：入口 HTML、manifest、图标以及同源静态资源（Cache Storage 名称 `mochi-v2`）。它**不会读取、缓存或上传 IndexedDB / localStorage 中的记录**。
- 无论是否启用离线缓存，记录始终只存在本地浏览器存储中。

## 7. 如何备份、导出与删除

### 导出备份（推荐定期做）

1. 打开麻薯底部导航的「**我的**」页。
2. 选择「导出全部记录（JSON）」：得到包含全部记录的 `.json` 文件（vault v2，顶层 `app` 标识为 `mochi`），可再次导入。
3. 或选择「导出 Markdown 合集」：得到一份便于阅读/迁移到其他工具的 Markdown 合集（注意：该格式目前不能导回麻薯）。
4. 把文件保存到你信任的位置（本地磁盘、加密网盘等），并妥善保管——其中包含收支与健康数据。

### 删除单条记录

在列表、编辑器或图谱的记录信息面板中删除；操作会立即写入本地存储。

### 删除全部数据

1. 「我的」页 →「清空全部记录」——会移除 IndexedDB 与 localStorage 中的全部记录（主题、引导标记和助手人设可能保留，可一并清除站点数据）。
2. 或在浏览器设置中清除该站点的数据（「网站设置 → 存储 → 清除数据」）。这会一并删除记录与偏好，且不可恢复。
3. 卸载「添加到主屏幕」的图标本身**不会**删除数据；需要在浏览器里清除站点数据才能彻底删除。

删除前请先导出 JSON 备份。删除操作不可撤销。

## 8. 第三方组件

麻薯的运行时依赖只有 `react`、`react-dom`、`markdown-it`，全部在你自己的浏览器中执行，不与它们的维护者通信。开发/发布工具（Vite、TypeScript、Vitest、`qrcode`、`qrcode-terminal` 以及截图脚本使用的本机 Chrome）只在本地运行。没有接入任何第三方服务、SDK、模型 API 或统计平台。

## 9. 政策变更

如果未来版本引入了需要联网的功能（例如可选的云同步，或路线图中的本站本地小模型适配器），我们会：

- 默认保持**关闭**，由用户主动开启；
- 在开启前明确说明会传输哪些数据、传到哪里（本地模型适配器仍应在设备本地运行）；
- 同步更新本文件与 README，并在版本说明中标注。

在此之前，本说明第 1、2 节所述行为不会改变。
